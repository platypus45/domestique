# Domestique — Python dependencies
#
# v4.0.0-alpha: the live-trainer runtime was removed, so the BLE/ANT+
# stack (bleak, pycycling, openant) is gone. The app is now planner +
# workout library + post-ride FIT import viewer.
#
# Upper bounds prevent a major-version upstream release (e.g. Pydantic 3,
# Starlette 0.40, FastAPI 0.120) from silently breaking a tagged build.
# Review + bump these deliberately when upstream majors roll.
fastapi>=0.119.0,<0.140
# Plain uvicorn (no [standard] extra) -- no WebSockets, no uvloop needed.
# httptools stays via uvicorn's own minimal deps if we want HTTP/1.1 parser
# acceleration, but even that is optional.
uvicorn>=0.30.0,<0.40
jinja2>=3.1.0,<4
httpx>=0.27.0,<1
fit-tool>=0.9.13,<1
pydantic>=2.0,<3
# starlette>=0.49.1 required: CVE-2025-62727 FileResponse Range-parsing DoS.
# Upper bound 2.0 admits starlette 1.x which fastapi 0.119+ uses.
starlette>=0.49.1,<2.0
# python-multipart is required by FastAPI for UploadFile / multipart form
# parsing; used by POST /api/ride/import.
python-multipart>=0.0.9,<1

# ZWO parsing (fallback to stdlib lxml if available for faster XPath; the
# app also works with xml.etree from stdlib alone).
lxml>=5.0,<7

# v1.0.2 IMPL-BANNER: explicit pin for `packaging.version.parse` used by the
# /api/update/check endpoint (already a transitive dep of fastapi/pydantic,
# but pinning here locks the version so the update-check banner doesn't
# silently break if a parent pulls a different range).
packaging>=23,<27

# v1.0.7 IMPL-TAU-FIT-CORE: scipy is needed by tau_fitting.py for nonlinear
# least-squares (`scipy.optimize.curve_fit`, Trust Region Reflective bounds)
# + the bootstrap-CI helpers. ~50 MB DMG hit is acceptable for the reliability
# gain over a hand-rolled Levenberg-Marquardt. Upper bound <2 keeps a future
# major-version release from silently breaking the fit (curve_fit behaviour
# changes have happened across major versions before).
scipy>=1.13,<2

# Desktop app (launcher)
pystray>=0.19.0
Pillow>=10.0.0
pywebview>=5.0
# v2.0.2 WIN-START-FIX: pywebview's Windows (EdgeChromium/WinForms) backend
# drives the .NET CLR via pythonnet — without it `webview.start()` aborts and
# the windowed EXE shows nothing. The `; sys_platform == "win32"` marker keeps
# pip from ever pulling pythonnet on macOS/Linux, so the DMG build and any
# `pip install -r requirements.txt` on a Mac are unaffected.
# NOTE: pythonnet only supplies the CLR bridge. The Microsoft Edge WebView2
# *runtime* is a separate OS prerequisite (the Evergreen redistributable; it
# ships preinstalled on Windows 11 but must be installed on older Windows 10).
pythonnet>=3.0; sys_platform == "win32"
